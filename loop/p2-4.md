# P2-4 Evidence-driven Completion

> P2-4 将“Agent 声称完成”升级为 Runtime 可验证的 Completion Decision。DONE 只能由 Runtime 根据持久化事实、验收状态、Review、Final Approval 与 Evidence 共同决定。

## 目标

- Agent 的完成声明不是完成条件。
- Evidence 必须关联当前 Run 和验收标准。
- failed / skipped / low-confidence / 跨 Run Evidence 不得证明完成。
- `READY_FOR_CONFIRMATION -> DONE` 必须通过 Completion Gate。
- Completion Gate 失败时必须进入 `BLOCKED`，不得降级为成功。
- Evidence 作为 Run 产物落盘到 `.loop/evidence/<run-id>/`。

## Runtime 流程

```text
Stage Executor
      ↓
Facts + Evidence
      ↓
Evidence Artifact
      ↓
Completion Gate
      ├── acceptancePassed
      ├── verificationPassed
      ├── reviewPassed
      ├── finalApprovalSatisfied
      └── valid Evidence
              ↓
           DONE
```

## Completion Gate

`loop/runtime/completion-gate.ts` 提供 `EvidenceCompletionGate`。

默认规则：

1. 当前状态必须为 `READY_FOR_CONFIRMATION`。
2. Acceptance、Verification、Review 必须全部通过。
3. Final Approval 必须满足且没有被拒绝。
4. 至少存在一条 Evidence。
5. Evidence 的 `runId` 必须等于当前 Run。
6. Evidence 必须为 `passed`，且不能为 `low` confidence。

任何条件失败都返回不可完成，并由 Runtime 转入 `BLOCKED`。

## 产物

Stage Executor 可以返回 `StageResult.evidence`。Runtime 会通过 `RunArtifactStore.writeEvidence()` 将 Evidence 持久化到：

```text
.loop/evidence/<run-id>/<evidence-id>.yaml
```

内容采用 JSON/YAML 兼容表示，并保留 `runId`、`criterion`、`status`、`confidence` 等 Completion Decision 所需事实。

## 测试

- Completion Gate 正常完成。
- 空 Evidence 阻断。
- 跨 Run Evidence 阻断。
- failed / skipped / low-confidence Evidence 阻断。
- Acceptance 未通过阻断。
- Execution Runtime 集成测试验证 `READY_FOR_CONFIRMATION -> DONE` 必须提供 Evidence。
