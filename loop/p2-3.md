# P2-3 Execution Runtime

> P2-3 将 Run Lifecycle、State Machine、Checkpoint 与 Stage Executor 串成真正可推进、可暂停、可恢复的执行循环。

## 目标

- 每次只推进一个业务阶段，避免一次执行跨越多个状态。
- 阶段完成后先持久化 Runtime Facts，再通过 Kernel 执行受保护的状态迁移。
- 在 `WAITING_FOR_GOAL_CONFIRMATION`、`READY_FOR_CONFIRMATION`、`PAUSED`、`DONE`、`BLOCKED` 处停止自动推进。
- `VERIFY` / `REVIEW` 失败进入 `FIX`，由 retry budget 限制修复次数。
- 所有恢复依赖持久化 Run State，而不是进程内状态。

## Runtime API

`loop/runtime/execution-runtime.ts`

- `step(runId)`：执行单个阶段并 checkpoint。
- `runUntilHalt(runId)`：持续推进直到遇到人工确认、暂停、完成或阻塞状态。
- `resetFixAttempts(runId)`：清理当前进程内的 retry 计数；事实状态仍以 Runtime State 为准。
- `StageExecutor.execute(stage, state)`：业务 Agent/工具层的唯一阶段执行接口。

## 执行边界

```text
INIT
  ↓
GOAL_REVIEW
  ↓
WAITING_FOR_GOAL_CONFIRMATION  ← 人工确认
  ↓
PLAN → IMPLEMENT → VERIFY
                  ↓       ↓
                FIX ←── 失败
                  ↓
                IMPLEMENT
                  ↓
                VERIFY
                  ↓
                REVIEW
                  ↓
READY_FOR_CONFIRMATION         ← 最终人工确认
                  ↓
                DONE
```

P2-3 不绕过 Kernel 的 Transition Guard、Policy Revision、Resource Lock 或 Capability Enforcement。
