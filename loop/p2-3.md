# P2-3 Execution Runtime

> P2-3 将 Run Lifecycle、State Machine、Checkpoint 与 Stage Executor 串成真正可推进、可暂停、可恢复的执行循环。

## 目标

- 每次只推进一个业务阶段，避免一次执行跨越多个状态。
- 阶段完成后先持久化 Runtime Facts，再通过 Kernel 执行受保护的状态迁移。
- 在 `WAITING_FOR_GOAL_CONFIRMATION`、`READY_FOR_CONFIRMATION`、`PAUSED`、`DONE`、`BLOCKED` 处停止自动推进。
- `VERIFY` / `REVIEW` 失败进入 `FIX`，由 retry budget 限制修复次数。
- 所有恢复依赖持久化 Run State，而不是进程内状态。

## P2-3.3 崩溃恢复

- `FileCheckpointStore` 将阶段完成 checkpoint 持久化到 `.loop/runtime/runs/<run-id>/checkpoint.json`。
- checkpoint 使用 `tmp + rename` 原子落盘，避免进程崩溃留下半写文件。
- checkpoint 携带 Run ID、Stage、输入 Fingerprint、Facts、下一状态和完成时间。
- Runtime 重启后发现当前 Stage 对应的完整 checkpoint，会恢复 Facts 并继续受保护的状态迁移，不重复调用 Agent/Tool。
- checkpoint 与 Runtime State 的输入 Fingerprint 不一致时直接 `[LOOP_BLOCKED]`，防止错误恢复。
- checkpoint 在状态迁移成功后清理；因此正常执行不会残留旧 checkpoint。
- 测试覆盖：跨实例读取、Agent/Tool 不重复执行、checkpoint 与 Runtime State 不一致时阻断。

## P2-3.4 持久化 Retry Budget

- `RuntimeFacts.fixAttempts` 是当前 Run 已消耗的 FIX 次数，属于持久化 Runtime State。
- 每次进入 `FIX` 前先从 Run State 读取 `fixAttempts`，递增后再执行 Agent/Tool；因此 Runtime 进程重启不会丢失 retry budget。
- `fixAttempts > maxFixAttempts` 时将 `fixAttemptsWithinLimit` 持久化为 `false`，随后通过 Kernel 转入 `BLOCKED`，不得继续执行 FIX。
- `resetFixAttempts(runId)` 会把次数和 guard 事实一起持久化清零，不依赖进程内 Map。
- `maxFixAttempts` 仍是 Execution Runtime 的运行策略参数；实际消耗次数以 Run State 为唯一事实来源。

## Runtime API

`loop/runtime/execution-runtime.ts`

- `step(runId)`：执行单个阶段并 checkpoint。
- `runUntilHalt(runId)`：持续推进直到遇到人工确认、暂停、完成或阻塞状态。
- `resetFixAttempts(runId)`：持久化清理当前 Run 的 retry 计数。
- `StageExecutor.execute(stage, state)`：业务 Agent/工具层的唯一阶段执行接口。

`loop/runtime/checkpoint.ts`

- `CheckpointStore`：Checkpoint 持久化抽象。
- `FileCheckpointStore`：项目 `.loop` 工作区内的 Run-scoped 文件实现。

## 执行边界

```text
INIT
  ↓
GOAL_REVIEW
  ↓
WAITING_FOR_GOAL_CONFIRMATION  ← 人工确认
  ↓
PLAN → IMPLEMENT → VERIFY
                  ↓       ↓
                FIX ←── 失败
                  ↓
                IMPLEMENT
                  ↓
                VERIFY
                  ↓
                REVIEW
                  ↓
READY_FOR_CONFIRMATION         ← 最终人工确认
                  ↓
                DONE
```

P2-3 不绕过 Kernel 的 Transition Guard、Policy Revision、Resource Lock 或 Capability Enforcement。
