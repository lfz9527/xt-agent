# P2-3.5 统一 Human Approval Gate

> 将 Run 级人工确认统一收敛为一个 Approval Gate，执行确认与最终验收共享同一套请求、策略校验、结果持久化和审计边界。

## 目标

- `WAITING_FOR_GOAL_CONFIRMATION` 使用 `execution` Gate。
- `READY_FOR_CONFIRMATION` 使用 `final` Gate。
- 审批结果持久化到 Run State 的 Runtime Facts。
- 审批等待期间发生 Policy Revision 变化时直接阻断，不接受旧策略下的审批结果。
- 审批请求与结果进入统一 Runtime Audit Log。
- 不把 Capability 级审批与 Run 级 Human Approval 混为一体。

## 设计

```text
                Human Approval Gate
                         │
          ┌──────────────┴──────────────┐
          │                             │
      execution                       final
          │                             │
 WAITING_FOR_GOAL_CONFIRMATION   READY_FOR_CONFIRMATION
          │                             │
 executionApprovalSatisfied      finalApprovalSatisfied
                                  finalApprovalRejected
```

## API

`loop/runtime/human-approval.ts`

- `request(runId, gate, reason, provider)`：统一发起人工审批。
- `resolve(runId, gate, decision)`：外部审批系统已完成审批时持久化结果。
- `HumanApprovalProvider`：与 UI、CLI、远程审批服务解耦。

`ExecutionRuntime`

- `requestHumanApproval(...)`：向统一 Gate 发起审批。
- `resolveHumanApproval(...)`：通过统一 Gate 写入审批事实。

## 安全约束

- Gate 必须确认当前 Run 的 Policy Revision 仍然有效。
- Gate 只允许在对应的人工确认状态生效。
- Execution Approval 只能满足 `WAITING_FOR_GOAL_CONFIRMATION -> PLAN`。
- Final Rejection 只能满足 `READY_FOR_CONFIRMATION -> FIX`。
- Final Approval 不直接写 `DONE`，仍必须通过 Kernel Transition Guard。
- Capability `confirm` 仍由 Kernel 的 `ApprovalProvider` 独立处理。

## 验收标准

- [x] execution / final 两类人工确认统一经过 Human Approval Gate。
- [x] 审批结果持久化到 Run State。
- [x] 审批过程中 Policy Revision 变化会阻断。
- [x] 审批请求与结果支持统一审计。
- [x] Vitest 覆盖批准、拒绝、非法状态和 TOCTOU 场景。
