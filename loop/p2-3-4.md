# P2-3.4 持久化 Retry Budget

> 将 FIX 重试预算从 ExecutionRuntime 的进程内状态升级为 Run State 的持久化事实，确保 Runtime 重启后不会丢失已消耗的修复次数。

## 目标

- `fixAttempts` 作为 Runtime Facts 持久化在 `.loop/runtime/runs/<run-id>/state.yaml`。
- 每次进入 `FIX` 时先读取持久化次数，再递增并落盘。
- 超过 `maxFixAttempts` 后持久化 `fixAttemptsWithinLimit: false`，并通过 Kernel 进入 `BLOCKED`。
- 新建 ExecutionRuntime 实例后继续使用原 Run 的 retry budget。
- `resetFixAttempts(runId)` 必须持久化清零。

## 设计

```text
Run State
  │
  ├─ facts.fixAttempts
  └─ facts.fixAttemptsWithinLimit
          │
          ▼
ExecutionRuntime(FIX)
          │
          ├─ 读取 fixAttempts
          ├─ +1
          ├─ 持久化
          │
          ├─ <= maxFixAttempts → Agent/Tool
          │
          └─ > maxFixAttempts → BLOCKED
```

## 约束

- 不使用进程内 `Map` 保存 retry budget。
- retry 次数属于 Run，不属于 Runtime 实例。
- `BLOCKED` 后不得通过 retry budget 自动恢复。
- State Guard 继续只消费持久化 Runtime Facts。
- 测试框架使用 Vitest。

## 验收标准

- [x] Runtime Facts 增加持久化 `fixAttempts`。
- [x] FIX 次数跨 ExecutionRuntime 实例保持。
- [x] 超限后进入 `BLOCKED` 且不执行 Agent/Tool。
- [x] reset 后持久化恢复为 0。
- [x] 相关 Vitest 覆盖跨实例、超限和 reset。
