# Deep Review

> 默认使用中文。代码、API、错误信息和命令保持原文。

## 目标

对整个项目进行周期性的系统性健康审查，识别短期 Review 不容易发现的长期技术债、架构漂移和治理问题。

## 触发

适用于周期性治理、重大版本发布前、架构重构后或主动执行的全面审查。

## Review Scope

```text
整个项目
  ↓
建立代码资产地图
  ↓
建立依赖与模块关系
  ↓
语义聚类 / 重复分析
  ↓
架构健康分析
  ↓
技术债与长期风险
```

## Preflight

识别语言、框架、Runtime、构建系统和测试能力，并加载 `code-review-rules/` 对应规则及项目级配置。

## 核心检查

- 核心代码资产分布
- 长期重复能力
- 模块耦合与架构漂移
- 循环依赖
- 技术栈和依赖碎片化
- Dead / obsolete code
- 核心模块复杂度与维护风险
- 测试覆盖薄弱区域
- 安全边界和高风险基础设施
- API / Domain / UI 层长期演化一致性
- 缺失的共享能力和治理机制

## 趋势

如果存在历史 Review 报告，优先比较问题数量、重复能力、架构风险和技术债趋势，而不是只输出一次性问题清单。

## Findings

按 `P0 / P1 / P2 / P3` 分级。同一问题只产生一个 Finding；高优先级问题必须有证据和 Confidence。

## 输出

中文项目健康报告、P0/P1/P2/P3 Findings、资产与架构观察、长期治理建议和最终结论。
