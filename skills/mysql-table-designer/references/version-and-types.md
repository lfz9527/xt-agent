# MySQL 版本与字段类型决策

仅在版本、数据类型、默认值、字符比较或敏感数据会影响设计时读取本文件。

## 兼容目标

- 用户指定 MySQL 版本时，以该版本为准，并避免输出该版本不支持或不执行的语法。
- 未指定时按 MySQL 8.0+ 设计并在假设中说明；不要默认为 8.4 专属能力。
- MySQL 5.7 不执行 `CHECK` 约束，不能把关键完整性仅寄托于 `CHECK`；需要改用可执行的结构设计、触发器或明确的应用校验说明。
- MySQL 8.0.16+ 才执行 `CHECK` 约束。表达式默认值及 BLOB/TEXT/JSON 默认值还存在更细版本差异，除非目标版本明确且确有业务需要，否则不要使用。
- `utf8mb4_0900_*` 排序规则属于 MySQL 8.0 系列；需要兼容 5.7 时选择该版本支持的 `utf8mb4` 排序规则。

## 数值

- 按最大预计值选择 `TINYINT`、`SMALLINT`、`MEDIUMINT`、`INT` 或 `BIGINT`，并明确是否允许负数。不要只因字段是主键就固定为 `BIGINT`。
- InnoDB 二级索引包含主键值；较长主键会放大所有二级索引的空间成本。
- 金额、税率、汇率和计量精度来自业务单位。先确定最大整数位和小数位，再选择 `DECIMAL(p,s)`。
- 必须精确的金额不用 `FLOAT`/`DOUBLE`；允许近似误差的科学测量数据可以使用浮点类型。
- 库存、数量、金额等已确认不能为负时，在兼容版本中增加命名 `CHECK`，并保留应用层输入校验。

## 字符串与二进制

- `VARCHAR(N)` 的长度由业务上限、协议限制和索引需求决定，不按示例机械取值。
- 固定长度编码在长度真正固定时才用 `CHAR`；二进制摘要、令牌或 UUID 的紧凑形式可考虑 `BINARY`/`VARBINARY`。
- 大文本根据上限选择 `TEXT` 系列。需要索引、排序或频繁过滤的内容应重新检查是否适合大文本字段。
- JSON 适合结构确实可变、整体读取且不需要大量关系约束的数据；不要用 JSON 替代稳定实体、关联表或需要独立索引的业务字段。

## 默认值与空值

- 业务必填字段通常使用 `NOT NULL` 且不设置默认值，让缺失输入直接失败。
- 只有“未提供就采用该值”符合业务规则时才设置默认值，例如明确的初始计数或创建时间。
- 可选字符串优先使用 `NULL` 表示缺失；只有空字符串本身是有效且不同的业务值时才保存空字符串。
- 唯一索引下，多个 `NULL` 与重复空字符串的行为不同。设计可选邮箱、手机号、外部编号时必须利用正确的空值语义。
- 不为密码哈希、令牌、身份证号、邮箱或业务编号设置空字符串默认值。

## 时间

- `TIMESTAMP` 保存和读取时受会话时区转换影响，适合明确采用 UTC/会话时区语义且范围满足要求的时间点。
- `DATETIME` 不自动进行会话时区转换，范围更宽，适合业务本地时间、未来排期或由应用统一处理时区的场景。
- 需要毫秒或微秒时显式选择 `DATETIME(3|6)` 或 `TIMESTAMP(3|6)`，并让默认值和更新表达式使用一致精度。
- `created_at`、`updated_at` 是否存在及由数据库还是应用写入，优先遵循项目约定。不要无条件添加 `ON UPDATE CURRENT_TIMESTAMP`。
- `deleted_at` 只在需求采用软删除时添加；软删除会影响所有唯一性和查询条件设计。

## 字符集与排序规则

- 默认字符集使用 `utf8mb4`。
- 排序规则必须匹配比较语义：是否区分大小写、重音、尾部空格、语言排序或按二进制比较。
- MySQL 8.0+ 可在需求允许时使用合适的 `utf8mb4_0900_*`；兼容 5.7 时使用该版本存在的规则，例如经确认后的 `utf8mb4_unicode_ci` 或 `utf8mb4_bin`。
- 用户名、邮箱、外部编码等唯一字段要同时考虑规范化策略。不要期待 collation 自动完成所有大小写折叠、去空格或 Unicode 规范化。

## 状态与敏感数据

- 状态码来自业务状态机。未提供枚举时不要发明 `1=启用、2=禁用`；可以使用中性类型并把枚举列为待确认项。
- 布尔字段可用 `TINYINT`，但仍需清楚定义 `0/1`；版本支持时用 `CHECK (column IN (0, 1))`。
- 密码只保存经认可算法生成的盐化密码哈希，字段名和注释应表达“哈希”而非可逆“加密”。
- 对身份证号、手机号等敏感数据，DDL 只能表达类型和必要索引；加密、密钥、脱敏、访问控制与审计策略必须在设计说明中单独声明，不能靠 COMMENT 视为已实现。
