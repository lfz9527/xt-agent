# 仓库规则解析

## 解析顺序

需要项目私有约定时，按以下顺序取值：

1. 用户在当前请求中的明确要求。
2. 当前仓库的 `CONTRIBUTING.md`、`AGENTS.md`、Git Hook、CI 配置或平台返回结果。
3. 仓库中明确命名的 Git 规则配置，例如 `.git-conventions.yml`。
4. 本 Skill 的默认建议。

只读取与当前 Git 操作有关的文件。不能访问远端策略或 Hook 时，标注“未验证”，不要把推测写成硬性规则。

## 默认值

- 默认远端名为 `origin`；如果不存在，先列出现有远端，不要自动创建或替换远端。
- 目标分支可按 `beta`、`main`、`master` 的顺序检测，但只有检测到实际存在的分支才可使用；都不存在时向用户说明，不要假定目标分支。
- 分支默认格式为 `<userSlug>/<type>/<snake_keywords>`，因此完整分支名包含两个 `/`；`userSlug`、`type` 和关键字内部不得再包含 `/`。
- 提交信息和 MR 描述的人类可读内容默认使用中文；类型前缀、文件名、API、错误码、Issue/commit 标识、URL 和平台关键字保留原文。用户明确指定其他语言，或仓库已有更高优先级语言规范时，再切换语言。
- 分支最大长度、类型列表、MR 字段和文件排除项属于仓库策略；没有证据时作为建议，不作为不可协商的全局规则。

## 规则冲突

如果用户要求、仓库配置和远端实际行为不一致：

- 不伪造“通过”或“违反”的结论。
- 先完成安全的只读检查。
- 明确指出冲突来源，并把需要用户决定的选项具体化。
