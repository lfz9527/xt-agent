# Issue 评论生成器

根据指定分支（默认当前分支）相对于对比基准分支（默认 `dev`）的 commits 和变更文件，生成结构化的 Issue 评论内容。**只生成纯文本，用户自行复制，不做任何 API 请求。**

## 为什么让 AI 来做这件事

写好一条 Issue 评论，核心能力是从零散的 git log 中提炼出有意义的概括——哪些改动属于同一个功能点、影响到了哪些模块、有没有遗留问题。这正是 LLM 擅长的模式识别和概括能力。所以你不需要逐条复制粘贴 commit message，而是理解改动的逻辑结构，再填充到合适的模板里。

## 核心原则

- **输出纯文本**：不调用任何 API 推送评论，用户自行复制
- **没内容就不写**：某个板块从 git 信息中提取不到内容，连着标题一起删掉，不空留标题
- **只总结，不做代码审查**：基于 git 事实提炼，不分析代码质量

## 工作流程

### 第一步：确定分支和对比基准

- 若用户指定了分支名，以该分支为准
- 若未指定，默认取**当前分支**
- 对比基准默认为 `dev`（用户可覆盖）
- 如果 `dev` 不存在，问用户"当前项目的基准分支是什么？"（可能是 `main`、`master`、`develop` 等）

### 第二步：判断分支类型，选择模板

从分支名判断类型。分支命名通常有自己的约定（如 `feat/login` 表示登录功能开发），根据分支名中的关键词推断：

| 分支名包含 | 类型 | 使用模板 |
|-----------|------|---------|
| `feat`/`feature` | 功能开发 | 模板 A |
| `fix`/`bugfix`/`hotfix` | Bug 修复 | 模板 B |
| `test` | 测试 | 模板 C |
| 无法判断 | 默认功能开发 | 模板 A |

如果某模板中的板块没有可填充的内容，连着标题一起删掉。

### 第三步：获取数据

执行两条命令获取填充材料。注意：如果用户指定了其他分支，下面的 `HEAD` 要替换为该分支名。

```bash
# commits 列表（基准分支之后的提交，不含 merge commit）
git log dev..HEAD --oneline --no-merges

# 变更文件统计（看改动了哪些文件）
git diff dev..HEAD --stat
```

**如果命令报错**（比如 `dev` 分支不存在），根据错误信息调整基准分支名重试，或直接问用户。

**如果 `git log` 没有输出**，说明当前分支和基准分支在同一位置，提示用户确认分支名或对比基准。

### 第四步：理解 commits 的含义

拿到 `git log` 输出后，不要逐条照抄。先整体看一遍所有 commit message，判断哪些 commit 属于同一个改动目标：

- 如果连续几条 commit 在描述同一个功能的不同侧面（如"添加登录表单"+"添加表单校验"），可以合并为一条"实现用户登录功能"
- 如果某条 commit message 写得不够清楚（比如只写了"fix"或"update"），结合它改动的文件推断它到底做了什么
- 目的是让每条总结后的功能点在逻辑上独立且可读，而不是罗列原始 commit 列表

### 第五步：填充模板

把提炼后的内容填入对应模板。某个板块没有可填充的内容，就连着标题一起删掉。

**关于标签**：模板 A（功能开发）默认使用 `#work` 标签，模板 B（Bug 修复）默认使用 `#good` 标签，模板 C（测试）默认使用 `#push_2` 标签。用户可以在请求时指定其他标签（如"标签用 #feat"），此时用用户指定的标签替换默认标签。用户未指定则用各自默认值。

**关于 MR 链接**：生成完评论内容后，询问用户是否有需要关联的 MR 链接。有则追加在末尾（多个链接每行一个），没有则不管。

## 填充细节提醒

- **实现的功能 / 问题描述 / 测试范围**：不要逐条复制 commit message，而是概括——把多个相关的 commit 合并为一条功能点。每个功能点用一句话说清楚做了什么
- **开发/设计思路**：从 commit message 和变更文件内容推断技术方案，说明为什么这么改、核心实现方式，不要罗列代码细节；如果 commit message 不足，可询问用户补充
- **发现的问题**：按问题逐条分点，每条包含问题现象、根因、对应的修复 MR 链接；MR 链接可以从 git log 或 Issue 评论中查找，找不到则询问用户
- **影响范围**：根据文件路径的目录层次推断。比如 `src/auth/login.tsx` + `src/auth/register.tsx` 可以概括为"认证模块"
- **文件变动**：直接从 `git diff --stat` 的输出提取，列出文件路径即可
- **删掉没内容的板块**：一个板块没有可填充的内容，就连标题一起删掉，不要留空标题
